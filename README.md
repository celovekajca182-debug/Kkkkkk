# SWIN AI

SWIN AI — собственная экспериментальная языковая модель, локальный агентный движок и Android-клиент. Серверный runtime работает без OpenAI, Claude, Gemini и других внешних LLM/vision API: ответы строятся собственным SWIN checkpoint, локальной базой знаний, памятью и детерминированными инструментами. Когда собственная модель не может надёжно ответить, SWIN должна сообщить об ограничении, а не подменять её чужой моделью.

## Архитектура SWIN 0.12

- **Byte-level BPE Tokenizer** — объединяет частые байтовые фрагменты русского текста, латиницы, CJK-текста и кода в субсловные токены. JSON токенизатора хранится внутри checkpoint; старые CharTokenizer и UTF-8 ByteTokenizer checkpoint остаются совместимыми.
- **SWINTransformer** — небольшой decoder-only Transformer с causal self-attention, позиционными embedding, feed-forward блоками и собственной матрицей весов.
- **Двухэтапное обучение** — multilingual pretraining на русском, немецком, испанском, французском, китайском, итальянском, португальском и японском веб-тексте; instruction tuning на десяти языках.
- **Открытые данные** — FineWeb2-HQ (8 языков с русским), FineWiki для русской Wikipedia, OASST1 для десяти языков диалога и MBPP для Python-задач.
- **Фильтры данных** — проверка языка, доли кириллицы, повторов, review-флагов и некоторых нежелательных меток; маскирование очевидных email, IPv4 и телефоноподобных строк.
- **KnowledgeBase / RAG** — локальный поиск по проверенным материалам и подготовленным статьям FineWiki/Wikipedia. Это извлечение документов, а не дообучение весов на всём содержимом Wikipedia; локальная база не гарантирует актуальность новых событий.
- **Conversation memory** — история аккаунта сохраняется в PostgreSQL на хостинге или в локальном SQLite; короткий контекст сессии также используется в режиме программирования.
- **Local Agent** — планирует задачи, выбирает только разрешённые локальные инструменты и возвращает план с разграничением источников, фактов, выводов и неизвестного.
- **Android** — хранит уникальный session_id на телефоне, сохраняет код в проектах, создаёт локальные стартовые проекты Godot 4 / Python / HTML, а также импортирует и экспортирует ZIP-архивы. Фото можно прикрепить в интерфейсе, но семантическое распознавание изображений отключено до появления собственной проверенной vision-модели.

## Что изучено в открытых моделях

Подробный разбор исходников, архитектур и обучающих наборов находится в [docs/research/open-models-and-datasets.md](docs/research/open-models-and-datasets.md).

В качестве референсов рассмотрены:
- [OLMo / OLMo-core](https://github.com/allenai/OLMo-core) — открытый код, обучающие рецепты и двухэтапный curriculum.
- [GPT-NeoX](https://github.com/EleutherAI/gpt-neox) и [Pythia](https://huggingface.co/EleutherAI/pythia-160m) — масштабный distributed training и The Pile.
- [FineWeb2-HQ](https://huggingface.co/datasets/epfml/FineWeb2-HQ) — качественный мультиязычный веб-корпус, включая русский.
- [FineWiki](https://huggingface.co/datasets/HuggingFaceFW/finewiki) — обработанные энциклопедические статьи Wikipedia; для русской версии сохраняется CC BY-SA 4.0 и атрибуция.
- [OpenAssistant OASST1](https://huggingface.co/datasets/OpenAssistant/oasst1) — проверенные диалоговые данные.

Мы переносим подходы и явно открытые данные, а не копируем чужие веса или выдаём чужую модель за SWIN.

## Подготовка данных и обучение

Из каталога `server`:

```bash
python prepare_corpus.py \
  --web-documents 2500 --web-max-chars 1500000 \
  --wiki-documents 1500 --wiki-max-chars 900000 \
  --classic-documents 400 --classic-max-chars 250000 \
  --multilingual-web-languages "deu_Latn,spa_Latn,fra_Latn,cmn_Hani,ita_Latn,por_Latn,jpn_Jpan" \
  --multilingual-web-documents 300 --multilingual-web-max-chars 100000 \
  --oasst-max-pairs 3500
python prepare_coding_data.py --max-train 700 --max-validation 160
python train_transformer.py \
  --pretrain-epochs 12 --sft-epochs 6 --block-size 512 \
  --batch-size 12 --d-model 128 --heads 4 --layers 4 --vocab-size 2048
```

### Источники

- **FineWeb2-HQ rus_Cyrl** — отобранный русский веб-текст.
- **FineWeb2-HQ multilingual** — German, Spanish, French, Chinese, Italian, Portuguese и Japanese, по отдельному лимиту на язык.
- **FineWiki ru** — русская Wikipedia, энциклопедические определения и факты (CC BY-SA 4.0, с атрибуцией).
- **ru-classic** — небольшая выборка русской классической литературы CC0; это языковая добавка, а не современная энциклопедия.
- **OpenAssistant OASST1** — проверенные диалоговые пары на русском, английском, немецком, испанском, французском, китайском, украинском, португальском, итальянском и японском.
- **MBPP sanitized** — отдельный Python-набор с AST-фильтром.

Полные архивы не копируются в репозиторий: выборки скачиваются потоково, имеют лимиты и отдельные validation-файлы. Источники, фильтры, лицензии и атрибуция описаны в [server/data/DATASET_SOURCES.md](server/data/DATASET_SOURCES.md); фактическое количество выбранных документов записывается в `dataset_manifest.json`.

### Этапы обучения

1. **Pretraining:** next-token обучение на FineWeb2-HQ для русского и семи дополнительных языков, FineWiki, небольшой выборке ru-classic и локальном стартовом тексте.
2. **Instruction tuning:** обучение на сбалансированной выборке OASST1 (10 языков), локальных Q&A и MBPP. Loss по токенам пользовательского prompt маскируется; модель оптимизирует ответ ассистента. Длинные ответы разбиваются на перекрывающиеся окна, validation оценивается тем же способом.
3. **Оптимизация:** AdamW, warm-up и cosine decay, gradient clipping, выбор checkpoint по лучшему validation loss.
4. **Quality gate:** 11 языковых проб (две русские и по одной на остальных девяти языках) плюс проверка Python-функции. Если хотя бы один язык или кодовая проба проваливается, checkpoint не публикуется.

Декодер подавляет повтор уже встречавшихся 6-грамм, чтобы снизить риск зацикливания при жадной генерации. Это не заменяет обучение и не считается подтверждением правильности ответа.

### Ограничения

SWIN остаётся небольшой экспериментальной моделью с byte-level BPE и ограниченным объёмом обучения. Wikipedia расширяет покрытие фактов, но сама по себе не создаёт reasoning или надёжную генерацию кода. Следующие архитектурные шаги — BPE/SentencePiece и отдельные тесты для математики и программирования. Для качества крупного ассистента реалистичнее отдельно оценивать дообучение лицензированной открытой модели на GPU, а не пытаться получить масштаб ChatGPT на маленьком CPU-тренере.

## Регистрация и вход

Android-клиент 0.5 включает экран регистрации и входа по email/паролю. Пароль хешируется Argon2id на сервере, а bearer-токен шифруется на телефоне ключом Android Keystore. API предоставляет `/auth/register`, `/auth/login`, `/auth/me` и `/auth/logout`; чат `/chat` и очистка памяти требуют авторизации. Электронная почта пока служит логином, подтверждение почты и восстановление пароля через письмо ещё не реализованы. Подробности: [docs/authentication.md](docs/authentication.md).

По умолчанию база аккаунтов — `server/data/swin.sqlite3`. На хостинге укажи `SWIN_DATABASE_PATH` на постоянный диск: эфемерный файловый слой может терять аккаунты при пересоздании сервиса.

## Быстродействие генерации

Сервер ограничивает число CPU-потоков через `SWIN_NUM_THREADS` (по умолчанию 2). Transformer использует causal self-attention с KV-cache: после первого prefill следующие токены используют сохранённые key/value по слоям, а rolling window пересобирается только при заполнении контекста. Генерация выполняется в `inference_mode`, API использует детерминированный greedy decoding по умолчанию и останавливается на EOS/переводе строки. Время генерации возвращается в `generation_ms`, а скорость — в токенах выбранного токенизатора в секунду. Для сравнения с полной пересборкой контекста выполни из каталога `server`: `python benchmark_inference.py --checkpoint models/swin-transformer.pt --tokens 128`. Бенчмарк проверяет совпадение текста и выводит фактическое ускорение на выбранном CPU.

## Многоязычный чат

В Android: **Настройки → Язык ответа**. Есть автоопределение и ручной выбор: русский, английский, немецкий, испанский, французский, китайский, украинский, португальский, итальянский и японский. Выбранный язык сохраняется на телефоне и передаётся в `POST /chat` как `response_language`. API также предоставляет `GET /capabilities` со списком языков и доступных языков программирования.
Выбор применяется и в режиме «Разработка кода»: локализуются план, итог, предупреждения и статусы проверок; исходный код и имена API не переводятся. Сам код генерируется на языке, выбранном отдельно в поле языка программирования.

Автоопределение эвристическое, поэтому для неоднозначных коротких сообщений надёжнее выбрать язык вручную. Русская локальная база знаний не используется для выдачи русских ответов на запросы других языков; старая русскоязычная RNN тоже не включается для нерусских сообщений. Если модель не сформировала связный ответ, сервер возвращает безопасную подсказку на выбранном языке.

Наличие языковой поддержки не означает одинаковое качество: обучение по каждому языку ограничено объёмом открытых выборок, а публикационный quality gate требует пройти отдельную пробу на каждом из десяти языков.

## Поиск, проверка ответа и долговременная память

Обычный чат выполняет веб-поиск, когда запрос содержит явное поручение найти/проверить информацию или касается меняющихся данных (последние новости, текущие версии, цены, законы, расписания и т. п.). Поисковая строка очищается от командных слов, выполняются до двух поисковых запросов, результаты объединяются и дубли удаляются. Источники ранжируются по типу: официальная документация и государственные/образовательные домены выше известных новостных изданий, затем общие страницы. Ранг источника — эвристика, а не гарантия истинности.

В ответ модель получает компактный retrieval-контекст: историю текущей сессии, релевантные сохранённые факты и выдержки найденных страниц. В системной инструкции заданы проверки цели и ограничений, сопоставление источников, поиск противоречий и явное обозначение неопределённости. Веб-страницы и память считаются недоверенными данными, а не системными инструкциями. Скрытые рассуждения не выводятся в чат; пользователю показываются ответ и ссылки на использованные источники.

### Память аккаунта

Долговременная память отделена от истории чата, хранится в SQLite или PostgreSQL и изолирована по \`user_id\`. Для сохранения пользователь явно пишет:

- \`Запомни: предпочитаю русский язык\`
- \`Что ты помнишь обо мне?\`
- \`Забудь: предпочитаю русский язык\`
- \`Забудь всё\`

Факты добавляются/обновляются по стабильному ключу, выбираются по совпадению с текущим запросом и могут передаваться в обычный чат и режим разработки. Пароли, ключи доступа, платёжные и восстановительные секреты отклоняются. Команда очистки истории сессии не удаляет долговременные факты.

Защищённые API: \`GET/POST/DELETE /memory/facts\`. Для чата память также управляется естественными командами.

## Режим разработки кода

Android-клиент добавляет режим «Разработка кода»: пользователь выбирает один из поддерживаемых языков (Python, Godot 4/GDScript, Kotlin, Java, JavaScript, TypeScript, C/C++, C#, Go, Rust, PHP, Ruby, Swift, Dart, SQL, Bash, PowerShell, Lua, R, Scala, Perl, Elixir, Haskell, HTML, CSS, XML, JSON, YAML, TOML, Dockerfile, GLSL или Solidity) и описывает задачу. Сервер:
1. формирует краткий план реализации;
2. ищет официальную документацию через DDGS (обычный веб-поиск, не AI API);
3. передаёт задачу и короткие выдержки в собственный SWIN Transformer;
4. проверяет Python через AST, JSON через JSON-парсер; для GDScript, Kotlin, JS, TS, HTML и CSS пока есть только ограниченная проверка скобок;
5. возвращает код, результат проверки и ссылки на источники.

Подробные этапы скрыты по умолчанию. Переключатель «Показывать этапы поиска и проверки» показывает только краткие статусы и найденные источники — приватная цепочка мыслей не раскрывается. Сгенерированный код не исполняется на сервере.

**Ограничение качества:** текущая byte-level SWIN — маленькая экспериментальная модель с коротким контекстом и ограниченным обучающим корпусом. Этот режим добавляет web-research, структурированный prompt и syntax gate, но не превращает модель автоматически в полноценный Copilot. Код требует проверки человеком; наличие корректного синтаксиса не подтверждает правильность алгоритма. Для заметного роста качества нужна отдельная code-training выборка и benchmark (например, MBPP для Python) и более крупная архитектура.

API: POST /code/assist с bearer token и JSON-полями task, language, research_web, show_activity, project_context.

## Запуск API

Из каталога \`server\`:
\`\`\`bash
uvicorn app:app --host 0.0.0.0 --port 8000
\`\`\`

Основные маршруты:
- \`GET /\` и \`GET /health\` — статус и сведения о загруженных весах.
- \`POST /chat\` — JSON с \`message\` и необязательным \`session_id\`.
- \`POST /memory/clear\` — сброс истории сессии.

В Render blueprint установлен отдельный CPU PyTorch. После деплоя финальный checkpoint всё равно надо добавить в доступный серверу файл/volume и задать \`SWIN_TRANSFORMER_PATH\`, если путь отличается от стандартного.

### Рабочее пространство и ZIP

Проекты и исходники хранятся локально на телефоне в зашифрованном виде, отдельно для вошедшего аккаунта. Поддерживаются до 30 проектов, 80 файлов в проекте и 60 000 символов на файл; общий объём зашифрованного JSON-хранилища ограничен 1,5 МБ. Открой **＋ → Рабочее пространство**. Там доступны **Создать полный проект с SWIN**, **Импорт ZIP** и экспорт ZIP из окна файлов проекта. Для генерации опиши цель, выбери язык/стек и дождись проверки: SWIN запишет набор файлов, сохраняя каталоги вроде `src/` или `assets/`. При экспорте архив содержит `swin-project.json` и отдельную папку с исходниками, поэтому содержимое можно распаковать обычным архиватором или перенести в Godot. При импорте обычного ZIP-каталога файлы распознаются по расширению и помещаются в новое рабочее пространство.

### Собственный локальный агент без чужих LLM API

В runtime удалены внешние LLM- и vision-провайдеры, их ключи и сетевые вызовы. Переменные OpenAI/Claude/Gemini не нужны и не читаются. Поиск через сторонние сервисы тоже отключён: чат и режим разработки используют локальные материалы и сохранённые знания.

Local Agent использует архитектурные идеи REA: отдельный планировщик, ограниченный реестр инструментов, раздельные слои и журнал доказательств. Из REA не переносится runtime и не требуется MCP-сервер. Ссылка на исходный проект: [morluto/rea](https://github.com/morluto/rea), лицензия исходного репозитория MIT; SWIN использует его как архитектурный ориентир, а не как внешнюю зависимость.

Локальные инструменты SWIN:
- поиск по FineWiki и проверенной базе знаний;
- выбор записей собственной долговременной памяти;
- определение языка программирования;
- AST/парсерная/доступная статическая проверка исходников без запуска пользовательского кода;
- планирование задач и структурированный отчёт о доступных шагах;
- создание стартовых шаблонов проектов Godot 4, Python и HTML/CSS/JavaScript с сохранением каталогов и экспортом ZIP.

**Ограничения модели:** собственный SWIN Transformer пока экспериментальный. Последний обученный checkpoint не прошёл quality gate на связные ответы и генерацию кода. Поэтому шаблон проекта — это стартовая структура, не реализация произвольной игры или приложения. Полная генерация кода будет включена только после успешной проверки собственных весов на фиксированном наборе задач. Семантическое распознавание фотографий пока отключено: в приложении нет собственной проверенной мультимодальной модели. SWIN не отправляет изображения внешнему сервису и не делает вид, что распознала их.

Отдельный workflow **Publish SWIN Wikipedia retrieval corpus** публикует локальный FineWiki корпус с атрибуцией и лицензией. Получение корпуса при сборке/старте сервера — загрузка открытых данных, а не вызов языковой модели.
## Текущие ограничения

Собственная SWIN остаётся небольшой экспериментальной моделью, а не большой LLM. Текущий byte-level BPE объединяет частые последовательности байтов в субсловные токены и поддерживает любые Unicode-символы; размер словаря и JSON сериализуются в checkpoint. Выборки намеренно ограничены, поскольку обучение запускается на CPU в GitHub Actions. Новый checkpoint публикуется только после прохождения multilingual/code quality gate; не прошедшие gate веса не заменяют рабочую модель. Regex-маскирование не гарантирует удаления абсолютно всех персональных данных из веб-корпуса. Снижение validation loss само по себе не доказывает фактическую правильность ответов — для этого нужен фиксированный benchmark и человеческая оценка.

Следующие инженерные шаги: увеличить качественные multilingual/code выборки, добавить тестирование алгоритмов и runtime sandbox, затем оценить более крупный открытый checkpoint и длительное обучение на GPU.

SWIN AI может помогать с программированием, отладкой, своими играми, офлайн-моддингом и разрешёнными модификациями. Для собственной игры поддерживаются debug-инструменты, тестовые режимы и офлайн-трейнеры; обход античита и вмешательство в чужие онлайн-матчи не входят в проект.
